# CivicHUD: จากจอ ESP32 สู่แอป Android แจ้งเตือนบำรุงรักษารถ

สถานะ ณ 14 ตุลาคม 2026 • เจ้าของโครงการ: armkong33120

โค้ดและเอกสาร: https://github.com/armkong33120/civic-hud (Private ต้องได้รับสิทธิ์เข้าถึง)

## เป้าหมายของโครงการ

CivicHUD มีหน้าที่ช่วยให้เจ้าของรถรู้ว่าเลขไมล์สะสมอยู่ประมาณเท่าไร และอีกกี่กิโลเมตรจะถึงรอบบำรุงรักษา เช่น น้ำมันเครื่อง ไส้กรอง น้ำมันเกียร์ และรายการที่เจ้าของรถกำหนดเอง เป้าหมายแรกคือการอ่านข้อมูลจาก OBD2 และให้ระยะคงเหลือลดลงตามการใช้งานจริง

รุ่น ESP32 เป็นระบบต้นแบบที่เคยนำไปขับทดสอบกับ Civic FC แล้ว ส่วนรุ่น Android กำลังออกแบบสำหรับผู้ใช้ประมาณ 20 คน ใช้งานฟรี แต่ละคนใช้หัว OBD2 ของตนเอง ล็อกอินเข้าแอปและเก็บข้อมูลบนคลาวด์ของเจ้าของโครงการ

## สิ่งที่มีอยู่แล้วใน ESP32

บอร์ดจริงคือ ESP32-2432S028R หรือ CYD จอสัมผัสขนาด 2.8 นิ้ว ความละเอียด240×320 แสดงสี RGB565 มี ESP32 แบบสองคอร์และ Bluetooth Classic ไม่ใช่ ESP32-C6 ตามชื่อแชทเก่า

เฟิร์มแวร์แยกงานเชื่อมต่อ Bluetooth/ELM327 ออกจากงานหน้าจอ มีตัวจัดการเลขไมล์ บันทึกสถานะลง NVS และเก็บประวัติ service ลง LittleFS โดยไม่ต้องใช้ SD Card หน้าจอมีภาษาไทย การแบ่งหน้า เมนูรายละเอียด การย้อนกลับ และรูดเพื่อยืนยันการบันทึก service

ได้เพิ่มหน้า CPU/RAM สำหรับดูค่าปัจจุบัน ต่ำสุด สูงสุด และปุ่มเปิด hotspot ตั้งค่าที่192.168.1.1 การเปิด hotspot จะพัก Bluetooth ก่อนเพื่อลดการใช้ RAM และปิด hotspot ก่อนกลับมาทำงาน Bluetooth

การวาดหน้าจอใช้การวาดเฉพาะส่วนที่เปลี่ยนด้วย sprite4-bit ขนาด240×48 ใช้พื้นที่5,760bytes จึงไม่ต้องจอง framebuffer ทั้งจอ การกระพริบบาร์วาดเฉพาะพื้นที่บาร์

## หลักการเลขไมล์ที่ต้องเข้าใจ

OBD2 adapter เป็นช่องทางสื่อสารกับ ECU ความสามารถอ่านข้อมูลขึ้นกับรถและคำสั่งที่รองรับ ไม่ควรสรุปว่ามี adapter แล้วจะอ่านเลขไมล์รวมหน้าปัดได้ทุกคัน

รถที่ทดสอบตอบ PID0131 ซึ่งหมายถึงระยะทางตั้งแต่ล้างรหัสปัญหา ไม่ใช่เลขไมล์ตลอดอายุรถ จึงใช้เลขไมล์หน้าปัดที่เจ้าของให้เป็นฐาน แล้วบวกระยะที่เพิ่มจาก ECU ต้องรักษาฐานและ checkpoint เป็นคู่ เพื่อป้องกันระยะซ้ำหลังขาดการเชื่อมต่อหรือ reboot

รอบทดสอบหนึ่งเริ่มจากเลขไมล์หน้าปัด298,785กม. ผู้ใช้รายงานหลังเดินทางว่าเลขไมล์ระบบต่างจากจริงราว100เมตร± ผลนี้เป็นประสบการณ์จากรอบทดสอบ ไม่ใช่การรับรองว่าทุก adapter หรือรถทุกรุ่นจะให้ความแม่นยำเท่ากัน

เมื่อข้อมูลขาด แอปควรแสดงว่ามีช่วงที่ไม่สามารถติดตามได้ และให้เทียบปรับฐานกับหน้าปัด หากใช้การคำนวณจากความเร็ว ต้องหยุดรวมระยะเมื่อข้อมูลค้างนานเกินเกณฑ์ ไม่ใช้ความเร็วล่าสุดลากยาวตลอดช่วงที่ Bluetooth หลุด

## ข้อตกลงเรื่องหน้าจอ

ผู้ใช้เลือกธีมกลางวันและกลางคืน ไม่มีไอคอนตกแต่งในชื่อรายการ ใช้ดำ เทา ขาว เขียว เหลือง แดง โดยบาร์ความเร่งด่วนมี24เฉดเรียงจากเขียวเข้มไปเขียวอ่อน เหลืองอ่อนไปเหลืองเข้ม และแดงอ่อนไปแดงเข้ม

บาร์ยาวขึ้นเมื่อใช้รอบบำรุงรักษาไปมาก เมื่อเหลือ500กม.หรือน้อยกว่าให้เป็นแดงเข้มกระพริบ รวมถึงกรณีเกินกำหนด จนกว่าจะบันทึก service ใหม่ รายการที่จำกัดเฉพาะเวลาไม่ใช้เกณฑ์500กม.นี้ ธีม ESP32ปัจจุบันสลับด้วยการแตะหัวจอ ไม่ได้เปลี่ยนอัตโนมัติตามแสง; เซ็นเซอร์แสงปรับความสว่างภายในธีม

ประวัติเปลี่ยนถ่ายเก่าบางรายการยังไม่มีข้อมูลที่เจ้าของยืนยัน จึงอาจขึ้นเกินระยะจำนวนมาก ต้องแก้ด้วยข้อมูลจริง ไม่สร้างประวัติขึ้นมาเพื่อให้หน้าจอดูดี

## แอป Android ที่ต้องการ

หน้าหลักแสดงเลขไมล์ สถานะ Bluetooth/ECU และรายการบำรุงรักษาพร้อมระยะคงเหลือ ตอนเพิ่มรถ ผู้ใช้ใส่เลขไมล์จากหน้าปัดและเลือก OBD2 จากนั้นแอปตรวจความสามารถการอ่านข้อมูลของรถคันนั้น

เมื่อบันทึกการบำรุงรักษา แอปเก็บวันที่ เวลา และเลขไมล์ พร้อมตัวเลือกบันทึกสถานที่ ร้าน ชื่อช่าง เบอร์โทร ค่าใช้จ่าย และหมายเหตุ ช่องเสริมข้ามได้ การเก็บพิกัดเป็นการเลือกบันทึกตอนทำ service ไม่ใช่ติดตามตำแหน่งตลอดการขับ

หน้าประวัติต้องดูย้อนหลังตามรถและรายการได้ ส่วนการแจ้งเตือนควรแจ้งตามรอบและไม่แจ้งซ้ำทุกครั้งที่ OBDส่งข้อมูล

## โครงสร้างระบบที่เสนอ

แอปอ่าน OBD2 และคำนวณระยะบนมือถือ บันทึกฐานข้อมูลในเครื่องก่อน เพื่อให้ทำงานได้แม้ไม่มีอินเทอร์เน็ต เมื่อออนไลน์จึงซิงก์ประวัติและข้อมูลที่จำเป็นขึ้นคลาวด์

ทางเลือกเริ่มต้นที่เสนอคือ Kotlin + Compose + Room สำหรับ Android ส่วนคลาวด์เป็นระบบบัญชี API และฐานข้อมูลหนึ่งชุด ยังไม่จำเป็นต้องเพิ่ม microservices หรือ load balancer จากจำนวนผู้ใช้20คนเพียงอย่างเดียว

ข้อมูลหลักประกอบด้วยผู้ใช้ รถ โปรไฟล์ adapter ฐานเลขไมล์ checkpoint/เที่ยวขับ รายการบำรุงรักษา ประวัติ service บันทึกการปรับเลขไมล์ และคิวซิงก์ ทุกข้อมูลบน server ต้องตรวจเจ้าของจากบัญชีที่ยืนยันตัวตนแล้ว

การบันทึก service และเริ่มรอบใหม่ต้องเป็นธุรกรรมเดียวกัน การซิงก์ต้องมีหมายเลข operation ไม่ซ้ำ เพื่อให้ส่งซ้ำหลังเน็ตหลุดได้โดยไม่สร้าง serviceซ้ำ ส่วนการแก้เลขไมล์ต้องมีประวัติและตรวจความขัดแย้ง ไม่เลือกค่าล่าสุดแบบเงียบๆ

สำหรับรุ่นแรกเสนอให้มีมือถือที่บันทึกระยะหนึ่งเครื่องต่อรถในช่วงเวลาเดียวกัน ก่อนจะเปิดหลายเครื่องพร้อมกันต้องกำหนดวิธีป้องกันการนับเที่ยวซ้ำ

## คลาวด์และ Azure

ผู้ใช้แจ้งว่ามี Azure Education พร้อมเครดิตUS$100 แต่สั่งพักการตรวจบัญชีไว้ ยังไม่ได้ยืนยันยอดคงเหลือ วันหมดอายุ รายการบริการ หรือสร้างทรัพยากรใด ข้อกำหนดใน repository จึงไม่ผูกกับบริการ Azure ที่ยังไม่ได้เลือก

การเก็บข้อมูล20คนสามารถเริ่มแบบเล็กได้ แต่ค่าใช้จ่ายจริงต้องประเมินตามบริการ ขนาดฐานข้อมูล backup และปริมาณ log หลังกลับมาตรวจบัญชี สิ่งที่ควรกำหนดล่วงหน้าคือการแยกข้อมูลผู้ใช้ การสำรองและกู้คืน การลบบัญชี และการเก็บข้อมูลเท่าที่จำเป็น

## ขอบเขตหลักฐานและข้อจำกัด

เฟิร์มแวร์ล่าสุดเคย compileและอัปโหลดแล้ว มี logและภาพหน้าจอเก่าเก็บไว้ใน repository ผลทดสอบสี24เฉด เกณฑ์500กม. และการวาดเฉพาะส่วนมีการตรวจด้วย host tests/stubs แต่ไม่ได้หมายความว่าผ่านการทดสอบกับโทรศัพท์หรือรถทุกแบบ

Hotspotเคยเปิด/ปิดสำเร็จบนบอร์ด แต่ยังไม่มีการยืนยัน HTTPผ่านโทรศัพท์จริง ช่วงหลังเปิด Wi-Fiยังพบ heapลดลงและมีหน่วยความจำเครือข่ายคงอยู่ ต้องตรวจต่อหากใช้งานส่วนนั้นหนัก

แอป Android, APK, login, backendและcloud deploymentยังไม่มี implementation ส่วน SDCard, RTCใส่ถ่านและการเปลี่ยนเป็น K-Line/CANแบบสายเป็นหัวข้อหารือ ไม่ได้ติดตั้งเพิ่มในงานนี้

## ให้ AI ตัวถัดไปเริ่มอย่างไร

ให้เข้าถึง repositoryก่อน แล้วอ่าน AI_HANDOFF.md ตามด้วย docs/CURRENT_STATE.md, docs/DECISIONS.md และ docs/ANDROID_SPEC.md เอกสาร PROJECT.md กับรายงานทีมเดิมเก็บไว้เป็นประวัติ อาจมีสถานะเก่าที่ถูกแทนด้วยข้อมูลใหม่แล้ว

งานที่เหมาะเริ่มต่อคือออกแบบหน้าจอ Androidและการเพิ่มรถ จากนั้นทำเส้นทาง offlineหนึ่งคันให้ครบ: เชื่อม OBD → อ่านข้อมูล ECUจริง → คำนวณระยะ → บันทึก checkpoint → ลดระยะบำรุงรักษา ก่อนเพิ่มบัญชีและการซิงก์

การอ่าน repositoryไม่ได้ทำให้ AIได้รับสถานะรันจริงหรือสิทธิ์บัญชีเดิมโดยอัตโนมัติ ต้องตรวจ environmentและสิทธิ์ใหม่ ห้ามรีเซ็ตเลขไมล์ ประวัติ หรือแฟลชบอร์ดเพื่อสาธิตโดยไม่ดูบริบทปัจจุบัน
